# Agent Note: 在升级期间生成隔离的 Web 启动器

Status: implemented

[English](2026-09-10-upgrade-web-launcher-generation.md) | 中文

## Problem

带版本号的 Windows Web 启动器包含目标代码目录、数据目录、发布版本和端口，因此复制上一次升级的文件可能遗漏启动器，或启动错误的安装实例。

## Decision

仓库提供 [`upgrade-web-launchers`](../../../../scripts/upgrade-web-launchers.ts)，根据明确的目标参数生成并验证完整的五文件启动器集合。`--write` 创建目标端口的文件，`--check` 拒绝缺失文件、内容漂移以及属于其他端口的启动器。该命令不会删除文件，因此过时的启动器会保留下来供操作者明确清理，而不会被静默丢弃。

升级 Skill 在确定目标数据目录和代码 worktree 后运行生成命令，并要求在启动前以及清理后运行只读检查。启动器内容来自一份目标描述，而不是复制上一次升级的数据目录。

## Alternatives considered

**复制上一次数据目录的启动器。** 否决，因为复制的文件名可能不完整，而且嵌入的版本、代码目录、数据目录或端口可能仍然过时。

**将启动器文件名加入数据迁移 manifest。** 否决，因为 manifest 记录持久化数据覆盖范围，而启动器正确性取决于渲染内容和目标启动参数。

**生成时删除所有其他端口的启动器。** 否决，因为升级流程不应在没有明确操作者决定时删除文件；检查会报告过时文件，并让清理责任保持明确。

## Consequences

每次 Windows Web 升级都有一个可复现的生成命令和一个只读启动器检查。检查对生成内容和端口归属保持严格，但过时启动器的清理仍然是显式操作。生成的启动器集合仅适用于 Windows；其他操作系统使用各自正常的进程启动方式。
