# Agent Note: 压缩继承匹配的推理等级

Status: implemented

[English](2026-08-14-compaction-inherits-reasoning-effort.md) | 中文

## 问题

直接压缩摘要器从已路由对话中选择提供方和模型，但遗漏了其推理等级。将缺失等级序列化为禁用推理 wire 值的适配器，可能发送已配置提供方拒绝的值，即使对话请求本身具有受支持的已选等级。

## 决策

当其提供方和模型与已解析的摘要目标匹配时，`summarizeWithLlm()` 会携带最新已记录的推理等级。没有匹配的已记录路由时，若该目标与 agent 目标匹配，它会携带 `AgentOptions` 的等级。显式配置且不同的摘要提供方／模型不复制该等级，而是解析自身的适配器默认值。

## 考虑过的替代方案

- **依赖适配器默认值**——不采纳：适配器对缺失设置的序列化方式可能与对话所选等级不同，使辅助请求无效而对话仍可成功。
- **向每个已配置摘要目标复制等级**——不采纳：对一个模型有效的等级可能不受另一个模型或提供方支持。
- **增加单独的压缩推理配置**——不采纳：现有已路由请求已记录用户所选的值；增加独立设置会使两类请求发生偏离。

## 后果

- 压缩对匹配的对话路由使用相同的已选推理等级。
- 不同的已配置摘要目标保留其适配器拥有的默认行为。
- 直接摘要器回归测试和真实 loop 的溢出恢复测试会断言已路由的 `max` 等级到达辅助请求。
